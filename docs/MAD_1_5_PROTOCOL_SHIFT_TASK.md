# MAD-1.5 protocol-shift task

Status: registered external-task development/replication plan; no effect
result has been run and no holdout claim is made.

## Why this is a different route

The existing 324 MatPES systems are closed to confirmatory relabeling. The
purpose of MAD-1.5 is therefore not to manufacture a MatPES holdout. It is a
new PBE-to-r2SCAN protocol-shift task in which the scientific question is
operational:

> Under a fixed number of expensive r2SCAN reveals, does a policy that sees
> only PBE observables find more target-protocol hull-supporting candidates,
> while preserving the complete revealed archive and reporting the cost of
> the policy?

This is a task-level method/mechanism result. It must not be described as an
independent MatPES generalization result, a paper-level holdout, or evidence
that IC-SARR is universally superior.

## Frozen task estimand

The unit is an exact chemical system. A system is eligible for the primary
mechanism table when it has at least 8 paired 3D-bulk candidates and at least
3 distinct stoichiometric compositions. The default query budget is

\[
B \in \{0,1,2,3,4,5,6\}.
\]

For each budget, report:

1. full-pool terminal target-hull confirmations;
2. final-causal confirmations among the selected trajectory;
3. the cumulative confirmation curve and its area under the curve;
4. wall-clock and phase-diagram construction cost;
5. paired system-level differences against source margin;
6. bootstrap intervals and win/tie/loss counts clustered by exact chemical
   system.

The target hull is composition-dependent and is recomputed from target
energies in the oracle vault. Querying a structure reveals its target energy;
the final-hull label is delayed and is never sent to the policy as a candidate
feature. All revealed target outcomes remain in the append-only archive.

## Policy and baseline contract

The first run compares only the already frozen policies:

- source margin;
- frozen IC-SARR / source-rollout implementation, once the MAD adapter has
  passed the existing action/reveal parity tests.

No MAD-specific score, posterior temperature, threshold, budget, or
composition fallback may be tuned after reading target outcomes. If an
adapter requires a new target-transport calibration, that calibration is a
separate development artifact and the policy checksum must be frozen before
the acquisition curve is read.

The policy-visible task contains PBE source observables, composition and
protocol fingerprints only. Target r2SCAN energies, target formation labels,
the complete oracle hull and unqueried target outcomes remain in the vault or
reveal boundary.

## Interpretation boundary

Positive evidence on this task would support only:

> Under the registered MAD-1.5 PBE-to-r2SCAN protocol-shift task and its
> fixed-budget oracle, the frozen policy has the reported acquisition-utility
> difference versus source margin.

It would not support an independent MatPES holdout claim, universal discovery
superiority, a memory/state-compression claim, or a causal-confirmation gain
unless those estimands separately pass their gates.

Negative evidence is still useful: it would show that the old development
signal does not transfer to this new protocol-shift task, without requiring a
new story about the 324 closed systems.
