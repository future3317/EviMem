## 结论

**有直接竞争，而且竞争已经不算弱。**
但在这次检索范围内，截至 **2026 年 7 月 15 日**，我还没有发现一篇论文同时覆盖：

> 冻结基础材料模型 + 持续接收 DFT/实验真值 + 固定容量 (K) + 有选择地保留 near-miss/失败记录 + certificate-compatible residual retrieval + 以稳定材料发现和 false-stable risk 为目标。

最危险的情况不是一篇论文完全撞车，而是审稿人认为：

> **EviMem-Mat = ResMem 的残差记忆 + lADS/OCS 的有限数据选择 + InvDesMobility 的可靠性证书 + MADE 的闭环材料发现环境。**

所以以下论文应该优先阅读。

---

## 第一优先级：最直接的三篇

### 1. **ResMem: Learn What You Can and Memorize the Rest**

**NeurIPS 2023，最直接竞争你的查询与预测机制。**

ResMem 在已有预测器外增加一个基于最近邻的 residual regressor，最终预测为：

[
\hat y(x)=f_\theta(x)+\hat r_{\mathrm{kNN}}(x).
]

这与你的“冻结材料 predictor，检索历史相似结构，用 oracle residual 修正预测”几乎完全重合。它还专门讨论了利用邻近训练样本应对 test-time covariate shift。([NeurIPS 会议论文集][1])

你重点阅读：

* residual 的定义和聚合方法；
* embedding 选择；
* 理论分析用了什么假设；
* kNN 邻居数量和数据规模；
* distribution shift 实验；
* 为什么 residual memorization 比直接 kNN label prediction 更好。

**它没有覆盖的部分：**

* 在线数据流；
* 固定 memory 容量和淘汰策略；
* DFT protocol compatibility；
* near-miss 的决策价值；
* 稳定材料发现指标。

因此，你不能把“检索 residual 修正冻结模型”作为核心创新，而必须把创新放在 **budgeted、decision-aware、certificate-aware memory selection** 上。

---

### 2. **Lifelong Machine Learning Potentials**

**JCTC 2023，加上 2025 年的后续工作，是材料领域最直接的持续学习竞争者。**

该工作研究机器学习势如何持续接收新的量子化学数据，并提出 lifelong adaptive data selection，简称 **lADS**。它通过 rehearsal 保留部分旧数据，持续缩减训练集，评估记录的重要性，并移除可能不一致或可疑的数据。([arXiv][2])

2025 年的后续论文进一步把 lMLP 用于连续的化学反应网络探索，明确区分：

* active learning 决定调用哪些新量子化学计算；
* continual learning 决定如何吸收新数据；
* lADS 决定哪些历史结构继续用于训练。

其改进版 lADS 可以仅保留一部分过去数据，同时维持旧任务性能。([arXiv][3])

这是对你最危险的材料领域先例，因为它已经包含：

* 连续到达的第一性原理数据；
* rehearsal buffer；
* 数据重要性排序；
* 删除冗余与不一致记录；
* 不确定性触发的新计算；
* 在线探索过程。

**你的关键区别必须明确：**

| lMLP/lADS                          | EviMem-Mat                        |
| ---------------------------------- | --------------------------------- |
| 持续更新模型参数                           | 基础模型完全冻结                          |
| memory 用于重训练/rehearsal             | memory 直接参与 test-time prediction  |
| 目标是防止遗忘、保持 PES 精度                  | 目标是降低筛选决策错误                       |
| 主要处理分子反应网络和势能面                     | 主要处理晶体稳定性和性质筛选                    |
| 选择代表性训练结构                          | 选择未来决策价值最高的 residual evidence     |
| 没有显式 DFT protocol certificate gate | protocol/source/version 决定证据是否可迁移 |

建议把 **lADS** 实现成材料领域强基线，而不能只用通用 reservoir 或 k-center。

---

### 3. **InvDesMobility: A Reliability-Gated First-Principles Feedback Framework for Closed-Loop Materials Discovery**

**2026 年 6 月的新论文，是 certificate、provenance 和 feedback-contract 叙事上最直接的竞争者。**

这篇论文强调：昂贵的第一性原理结果只有在证据充分时才能进入反馈循环；不能只保存最终标量，还要记录中间结果、拟合质量、收敛历史和 workflow assumptions。它提出 reliability-gated DFT feedback、evidence stratification、provenance recording 和 auditable release。([arXiv][4])

论文还把反馈拆成不同对象：

* relaxed structures 用于更新生成模型；
* 通过质量控制的 mobility channels 用于训练 acquisition model 和安排验证优先级；
* 只有通过可靠性 gate 的结果才进入下一轮。

这与你的以下概念明显重合：

* MaterialMemoryCard；
* protocol certificate；
* evidence quality gate；
* source/provenance；
* 只有可信 oracle 结果才能写入 memory；
* 结构化反馈对象而不是单一 label。

**它没有解决：**

* 固定 memory 容量 (K)；
* memory eviction；
* near-miss 和 false-stable 的特殊价值；
* frozen predictor；
* local residual correction；
* 跨数据库 certificate-compatible retrieval；
* Matbench Discovery 稳定材料筛选。

因此你最好避免把贡献表述为：

> 首个带有 evidence/provenance gate 的第一性原理反馈系统。

更安全的表述是：

> 首个研究在固定容量下，如何保留和检索 protocol-compatible prediction residuals，以优化未来稳定性筛选决策的系统。

---

## 第二优先级：闭环发现和 oracle-budget 竞争

### 4. **MADE: Benchmark Environments for Closed-Loop Materials Discovery**

MADE 将材料发现正式构造成闭环过程：

[
\text{propose candidates}
\rightarrow
\text{oracle formation energy}
\rightarrow
\text{update strategy}
\rightarrow
\text{next iteration}.
]

它围绕热力学稳定材料发现，限制 oracle budget，并比较不同生成器、过滤器、规划器和 discovery policy。([arXiv][5])

这意味着你不能声称：

* 首个在线材料发现 benchmark；
* 首个带 oracle feedback 的稳定材料发现系统；
* 首个有预算约束的闭环材料发现问题。

但 MADE 主要约束的是：

[
B=\text{oracle-call budget},
]

而你可以增加另一个独立维度：

[
K=\text{long-term memory budget}.
]

最合理的关系是：

> MADE 研究在有限 oracle budget 下查询什么；EviMem-Mat 研究已经获得 oracle 结果后，在有限长期 memory budget 下记住什么。

MADE 很适合作为你的第二主 benchmark，甚至比人为构造 Matbench Discovery 在线顺序更自然。

---

### 5. **Surrogate-Gated Generation and Foundation-Model Embeddings for Bayesian Materials Design**

这篇 2026 年 6 月论文在闭环晶体生成系统中加入：

* 冻结或预训练材料表示；
* Gaussian process surrogate；
* uncertainty-aware acquisition；
* diversity selection；
* 固定的每轮 oracle-call budget；
* 根据历史 oracle 数据持续更新 surrogate；
* 因果 replay 评估。

论文明确将已验证结构称作闭环的 long-term memory，并专门避免使用完整 memory 预测其中已有样本所造成的 memorization leakage。([arXiv][6])

它与你重叠的部分是：

* 历史 oracle 结果作为长期状态；
* foundation-model embedding；
* uncertainty 和 diversity；
* 固定预算公平比较；
* 用历史结果校准后续候选排序；
* closed-loop discovery curve。

它的核心仍是 **oracle acquisition gate**，而不是有限容量 memory retention：历史数据基本都可用于 GP 更新，没有重点研究该淘汰哪条记录。因此它更像端到端系统竞争者，而不是直接算法等价物。

---

### 6. **CrystalGym: A New Benchmark for Materials Discovery Using Reinforcement Learning**

CrystalGym 提供可以直接返回 DFT 性质的在线强化学习环境，包括 band gap、bulk modulus 和 density。系统逐步构造晶体，完成后调用 DFT 计算 reward。([arXiv][7])

它不直接研究 memory eviction，但会限制你对“实时 DFT feedback 环境”的新颖性表述。

它更适合做扩展实验，不一定需要作为主 benchmark，因为你的方法针对的是已有候选池上的筛选与误差修正，而 CrystalGym 更偏生成策略学习。

---

## 第三优先级：protocol 和跨理论迁移竞争

### 7. **Cross Learning Between Electronic Structure Theories for Unifying Molecular, Surface, and Inorganic Crystal Foundation Force Fields**

这篇工作研究如何在不同电子结构理论和数据域之间联合学习，提出 multi-head replay post-training，并使用代表性的旧数据 replay 以防止跨理论适配时发生遗忘。([arXiv][8])

它会直接影响你对“不同 DFT protocol 不可直接混合”的处理方式。审稿人可能会问：

> 为什么使用硬 certificate gate，而不是像 multi-head 或 multi-fidelity learning 那样学习不同 protocol 之间的映射？

你需要比较至少三种策略：

1. naive pooling：忽略 protocol；
2. hard certificate gate：只使用完全兼容的记录；
3. learned protocol transport：允许不同 protocol 间经过校准后迁移。

这样才能证明 certificate 不是简单 metadata filter。

---

### 8. **Calibrating DFT Formation Enthalpy Calculations by Multi-Fidelity Machine Learning**

该工作使用多保真模型学习实验 formation enthalpy，并校准 Materials Project 中的 DFT formation enthalpy，进而寻找可能被 DFT 低估稳定性的材料。([arXiv][9])

它不是在线 memory 方法，但会竞争你的“使用 residual 校准形成能并改善稳定材料发现”叙事。

区别在于它：

* 训练一个全局 multi-fidelity model；
* 不处理 streaming memory；
* 不限制历史记录容量；
* 不做 query-local retrieval；
* 不研究 near-miss retention。

不过它应该作为 protocol calibration 的强静态基线。

---

## 通用 ML 方法中必须阅读的两篇

### 9. **Online Coreset Selection for Rehearsal-Based Continual Learning**

**ICLR 2022。**

OCS 在线选择同时具有代表性、信息量和与历史任务高 affinity 的样本，用于有限 replay memory。([开放评审][10])

它会直接竞争你的：

* residual/loss-aware；
* novelty；
* diversity；
* history compatibility；
* fixed-budget online selection。

虽然它依赖梯度并服务于模型重训练，但你应该将其思想适配成一个强基线。否则仅比较 FIFO、reservoir、uncertainty 和 k-center，基线强度可能不够。

---

### 10. **GoTTA Be Diverse: Rethinking Memory Policies for Test-Time Adaptation**

该工作把 memory 视为 test-time adaptation 中独立的 first-class component，系统研究紧张容量、时间相关流和非独立同分布数据下的 memory policy，重点比较 class balance、uncertainty 和 feature-space diversity。([arXiv][11])

其核心观点是：即使 memory 已经按类别平衡，近重复样本仍然会浪费有限容量，因此要使用 farthest-point 或 cosine-diversity 等策略。

需要注意，这篇是 ICLR 2026 投稿但没有被会议接收；不过它的实验设计仍然值得参考。([开放评审][12])

它非常适合作为 EviMem 中 diversity/k-center 部分的对照，但它使用无标签 test-time stream，不涉及可靠 oracle label 或材料 protocol。

---

## Benchmark 论文仍然必须精读

### 11. **Matbench Discovery**

这不是方法竞争者，但它决定你的主要结论能否成立。

Matbench Discovery 明确指出，formation-energy regression 指标与真实稳定性发现指标并不总是一致，尤其是 convex-hull 边界附近容易产生 false positives；它报告 precision、recall、F1 和 discovery acceleration 等任务指标。([arXiv][13])

你的 near-miss 概念最适合从这里正式定义，例如：

[
\mathcal N_\epsilon
===================

{x:0<E_{\mathrm{hull}}(x)<\epsilon},
]

或者定义为基础模型预测 stable、oracle 最终判为 unstable 的 false-stable 集合，而不是泛称“失败样本”。

---

## 推荐阅读顺序

先读这四篇：

1. **ResMem**：确认 residual correction 还能剩下多少算法新颖性；
2. **Lifelong Machine Learning Potentials / lADS**：确认材料领域选择性历史数据保存已经做到什么程度；
3. **InvDesMobility**：重写你的 certificate 和 evidence-card 新颖性声明；
4. **MADE**：确定最终闭环 benchmark 和 oracle/memory 双预算设定。

然后读：

5. Surrogate-Gated Generation；
6. Cross Learning；
7. OCS；
8. Matbench Discovery。

## 目前最危险的新颖性边界

读完上述论文后，你的核心不能只是：

> 保存高残差、边界附近且多样的 DFT 样本，并用 kNN residual 修正冻结预测器。

这很容易被拆解成已有组件。更能守住新颖性的版本是：

> **在非平稳材料筛选流中，学习一个 protocol-conditioned、decision-aware 的 streaming residual coreset；在固定容量下，优化未来稳定性筛选风险，尤其是 false-stable cost，并在证据缺乏或协议不兼容时拒答。**

其中真正可能成为 ICLR 方法贡献的部分是：

* memory utility 直接由未来 discovery loss 定义；
* protocol compatibility 进入选择和检索的数学目标，而不是后处理；
* fixed-(K) 在线更新具有近似保证或风险界；
* near-miss 是 decision-risk 推导出的结果，不是手工加权特征；
* 在相同 oracle sequence 下胜过 ResMem+lADS/OCS；
* 在相同 oracle budget 下胜过 MADE 中的静态或持续重训练策略。
